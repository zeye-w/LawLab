# LawLab · P1 第二批：二级法律知识网络

本分支基于 PR #19（`feat/registry-backed-knowledge-authorities`），是**依赖式/stacked PR**。在 #19 审核合并前不要直接把本分支改为 `main` 的基础；#19 合并后，应把本 PR 的 base 更新到 `main` 并重新执行 CI。

## 结构与交互

- 原 9 个教学总览概念保持原身份、原关系及默认 2D/3D 视图，不直接在总览展示 20 个节点。
- 新增 11 个二级概念，采用稳定 `concept:cn:<legacyId>` 与 `parentId`；其中合同义务 5 个、证据评价 4 个、请求权基础 2 个。
- 选中上述父节点，点击“展开 N 个二级概念”，2D 和 3D 同时切换到 **1 个父节点 + 直属子节点**的简化图；点击子节点仍显示来源与学习问题。
- “返回全部概念”恢复总览与父节点选中状态；浏览器内保存的 2D/3D 选择不因展开或收起而改变。
- 作用域数据来自 Registry 的 `knowledgeBranchNodes(parentId)`，双方图谱使用相同 `concepts` 参数。语义相邻关系独立于父子层次，避免“父节点”错误地被解释为法律效力上位规范。

## 新增内容（只供学习，待人工核验）

| 父节点 | 子概念 |
| --- | --- |
| 合同义务 | 合同成立、合同效力、合同履行、违约责任、合同解除 |
| 证据评价 | 真实性审查、合法性审查、关联性审查、电子数据核验 |
| 请求权基础 | 构成要件分析、请求与抗辩检验 |

本轮新增描述使用有条件的学习提示，**不产生针对具体案件的法律结论**。个别概念关联 PR #19 中已有的官方条文**候选来源**，但这些来源仍为 `pending`、`validity=unknown`；没有合适候选来源时显示“尚未录入”，不伪造条文。

## 数据约束

- Registry 的 `parentId` 必须引用真实父概念，且同法域、同学科分类；本阶段最多两层，防止无意产生不可导航的深层图。
- 原始概念总览仍通过 `legacyConceptView()` 返回根节点；新的 `getConceptChildren()`、`knowledgeBranchNodes()` 提供局部视图。
- 绘制层接受稳定数组作为概念输入，切换主题时清理旧的 Canvas 监听与模拟状态。
- `npm test` 加入层级选择、父子关系、子图投影、法律依据待核验和键盘可操作按钮的回归。

## 验收建议

1. 桌面知识图谱选择“合同义务”→展开→在 2D/3D 间切换→选择“违约责任”→返回总览。
2. 移动端默认 2D，展开与 Tab/Enter 仍能选中子节点，页面可纵向滚动。
3. 展开“证据评价”和“请求权基础”；其他六个根节点保持原样。
4. 文字、条文来源标记不出现“已核验”假阳性；切换节点不改变用户记忆卡进度。
5. #19 合并后更新本 PR base 至 `main`，检查合并后的 2D/3D、条文引用和全量测试。

此版本优先把**知识结构与导航能力**做扎实；法条效力人工核验和完整案例库属后续独立工作。
